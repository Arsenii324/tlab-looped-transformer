## Результат

Лупд-трансформер переиспользует один блок много раз, покупая вычисления, но не покупая параметры.
Область запускает мало лупов, потому что выигрыш рано выходит на плато, и объясняет это тем, что
отображение лупа сходится: за неподвижной точкой считать уже нечего. **Здесь отображение не сходится
вовсе, а выигрыш всё равно выходит на плато, и причина другая: луп с разделёнными весами проходит
глубины, которые не может различить.** 32 вектора ключей, которые токен порождает по одному на луп,
занимают эффективный ранг **~1.6 из 32** — то есть внимание или отбор по ним близки к усреднению с
лишними шагами, и всякому механизму, которому нужно различать глубины, работать не с чем. Мы
построили эксперимент, который мог бы это объяснение опровергнуть, зарегистрировали его критерий
заранее, и оно устояло на двух сидах.

Это и есть измеренная причина того расхождения, в которое упирается вопрос задания: **двенадцать
вмешательств, пять понижают лосс, и ни одно не расширяет диапазон лупов, остающихся полезными.**

## Что сработало

Приведено до отказов, потому что дальше страница состоит в основном из отказов.

- **Убрать нормализацию между лупами: ≈ −0.68 нат**, крупнейший одиночный эффект в проекте. Дефолт
  области для этой архитектуры неверен: с нормализацией отображение стягивается к неподвижной точке
  к лупу ~16 и вовсе не накапливает выигрыш от лупов.
- **Отжиг супервизии расширяет полезную полосу на 6 из 6 веток при нуле добавленных параметров.**
  Самый подкреплённый результат здесь и единственный, проверенный и на двух бюджетах, *и* прогоном
  по допуску. **Лосс он не понижает.**
- **Доведение бюджета токенов до конца: 0.39–0.42 нат** при переходе 46M → 90M против 0.002–0.26 у
  любого архитектурного вмешательства здесь. **Данные стоят больше, чем любое из них.**
- **Exclusive self attention: −0.2162 / −0.2633** на двух сидах, ноль параметров. Воспроизводится —
  но 84–91% эффекта приходится на один луп, то есть он улучшает блок, а не лупинг, и на масштабе не
  проверен.

## Ответ на постановку задачи, в шести частях

1. **Диагноз из самого задания здесь не подтверждается.** Оно объясняет насыщение сходимостью в духе
   DEQ. Состояние этой модели не сходится: единичный вектор дрейфует *логарифмически* (R² **0.986**
   на одном параметре против **0.748** у сходящегося степенного закона; ρ > 1 на всех измеренных
   глубинах; 0.18 рад продолжает накапливаться между лупами 129 и 384). Насыщение наступает на лупе
   ~8 независимо от этого. Дрейф архитектурный: необученная модель той же формы дрейфует *быстрее*.

2. **Почему глубины неразличимы и почему это не артефакт малой модели.** Причина — асимметрия
   проекций. Неразделённый стек строит почти ортогональный набор ключей из потока состояний, *столь
   же коллинеарного*, как у разделённого (**4.36** против **1.40** из 33), просто потому что у
   каждого слоя своя `W_K`; одна общая проекция купить этого не может ни при какой ширине
   `[RANK-PROJECTION]`. Коллапс присутствует при инициализации, после обучения сильнее, и он **ровен
   на диапазоне hidden 224–896** — от 2.73M до 32.58M параметров, разброс 0.062, без тренда (§4.31).
   Он объясняет опубликованные положительные результаты в этом семействе, измеренные на
   неразделённых стеках, а не противоречит им. *Одна ветка попыталась выкупить ранг обратно: четыре
   различные проекции дают **8.818/32** при инициализации и **1.74** после обучения, то есть обучение
   воспроизвело коллапс. Эта ветка — n = 1, и она **не прошла собственный зарегистрированный
   критерий**, поэтому причинный вопрос остаётся нерешённым, а это — вспомогательная деталь, а не
   несущее утверждение (§4.30).*

3. **Сильнейшая идея, которую мы проверяли, — потокенное смешивание по глубинам, и мы построили
   эксперимент, способный опровергнуть наше же объяснение того, почему оно не работает.** Идея:
   разным токенам нужно разное количество вычислений, значит модель должна научиться взвешивать
   состояния, которые порождают её лупы, или отбирать среди них. Наш прежний гейт проверить это не
   мог — он схлопывался на один луп и ничего не смешивал. Замена масштабно-инвариантна, и она
   действительно распределяет вес: **при 8 лупах эффективно использует 7.58 из них; при 16 — 14.96;
   при 32 — 29.84**, и ни один токен не кладёт больше 0.99 своего веса на один луп. **Критерий был
   зарегистрирован до появления ветки:** *если смешивает и всё-таки выигрывает, наше объяснение
   неверно.* Он смешал. Он выиграл **−0.0012 / +0.0023** на двух сидах — то есть ничего. Работающая
   смесь поверх неразличимых глубин не даёт ничего. Смешивание по глубинам атаковано семью
   способами; каждый — нуль, отказ инструмента или выигрыш, у которого не прошла собственная
   проверка механизма (`RESULTS.md` §1b).

4. **Двенадцать вмешательств. Пять понижают лосс. Ни одно не расширяет полезную полосу**, ни при
   одном проверенном допуске. Четыре из пяти дают **67–101%** своего выигрыша на одном лупе, где их
   собственный механизм доказуемо бездействует: LoRA 67–95%
   `[POSTHOC-LORA-RANK]` `[CAPACITY-NOT-DIVERSITY]`, XSA 84–91% `[XSA-AT-R1]`, duo-causal при W = 3
   78–101%, насыщающийся гейт глубины 96%. Они улучшают блок, а не лупинг. Пятое устроено наоборот:
   штраф на норму выигрывает по перплексии (**37.52** против **38.86**) за счёт ухудшения лупа 1
   (`ΔCE@1 = +0.2263`). А то единственное, что воспроизвелось на трёх платформах, исчезает при
   бюджете в 5× больше: **−0.0936** на 2.5M против **+0.0077** на 12M в паре с идентичным конфигом.
   **В этом проекте нет ни одного воспроизведённого улучшения CE на масштабе.** (§4.29; что уцелело —
   `RESULTS.md` §1b.)

5. **Один рычаг двигает глубину, стоит ноль параметров и проходит те две проверки, на которых
   остальные споткнулись.** Отжиг супервизии расширяет полосу на **6 из 6 сидов**, с одинаковым
   разложением по краям на 2.5M и на 10M. На прогоне по всем целым глубинам 12–32 отожжённые ветки
   держатся в пределах допуска на **2.1× и 2.0×** большем числе глубин, чем их контроли. Это
   единственное утверждение о полосе здесь, устойчивое к допуску плато, разрешённое с точностью до ±1
   лупа и воспроизведённое по сидам. **Лосс он не понижает**; эта половина утверждения отозвана.
   (`METHOD.md` §2 — про отзыв и его шесть точек; §4.25c — про прогон.)

6. **Потокенная потребность в глубине реальна и недостижима — этому посвящён `EARLY_EXIT.md`.**
   Свидетельство «реальна» — надёжность по split-half, **0.866** против нуля **0.0007**, а вовсе не
   оракульный запас в 0.3084 нат, у которого оба нуля специфицированы неверно: они разрушают
   гладкость кривых отдельных токенов (в 4.6× грубее) и дают запас *больше*, чем реальные данные
   (**0.3877**, **0.4110**). Восемь правил из пяти классов инструментов забирают из него не более
   **0.1%** — по причине из части 2.

Отрицательный результат с измеренным механизмом, один рычаг, работающий на той оси, на которой он
работает, и отчёт о том, что было испробовано и что не сработало.

## Замечания для чтения

*Служебное, вынесено сюда, а не выше.*

### Как считать параметры: очевидный способ даёт неверный ответ

Сумма по `state_dict` чекпойнта даёт **10,899,616**, то есть выше лимита. Это артефакт разделения
весов: `lm_head` и `embed` — один и тот же `nn.Parameter` под двумя именами, поэтому `state_dict()`
считает разделённый эмбеддинг дважды, а `.parameters()` дедуплицирует. Разница ровно равна
`vocab × hidden = 4096 × 448 = 1,835,008`, и `10,899,616 − 1,835,008 = 9,064,608`. Проверять через
`sum(p.numel() for p in model.parameters())` — именно так получены все числа здесь. Иначе
проверяющий, взявшийся за самое жёсткое ограничение задания очевидным способом, заключил бы, что
модель дисквалифицирована (`report.md` §6.0, строка 27). Голый `Config()` печатает **9,065,056**,
потому что его умолчание `state_renorm=True` — это как раз та ветка, которую отчёт отвергает; в
выложенной модели `state_renorm=False`.

### Как считаются вмешательства, чтобы все документы сходились

**Двенадцать вмешательств: одиннадцать механизмов в модели, один рычаг в расписании лосса.** Три из
одиннадцати запускались в двух настройках каждый (LoRA с рангом 2 и рангом ≥ 4; duo-causal внимание
при W = 2 и W = 3; потокенный гейт глубины в ненормализованном и масштабно-инвариантном вариантах),
поэтому в `RESULTS.md` §2 строк больше, чем механизмов. Ненормализованный гейт глубины проходит как
отказ инструмента, а не как результат: он насыщается до жёсткого argmax и вовсе не способен выразить
смешивание — поэтому он строка, но не утверждение. Где бы в этой папке ни встретился счёт, он этот.

### Токены в квадратных скобках

`[POSTHOC-LORA-RANK]`, `[CAPACITY-NOT-DIVERSITY]`, `[XSA-AT-R1]`, `[WITHDRAWN-ANNEAL-CE]` и
`[RANK-PROJECTION]` — не недоделанная разметка. Каждый помечает утверждение, которое было
**ослаблено или отозвано**, и `src/check_caveats.py --strict` роняет сборку, если какой-то документ
приводит числа такого утверждения без его токена. Так оговорка не может уцелеть в одном файле и
потеряться в другом. Проверка появилась потому, что ровно это произошло трижды за один вечер
(`FAILURES.md`).

### Три термина, определённые один раз

- **полезная полоса**: непрерывный участок числа лупов, на котором CE на валидации не хуже лучшего
  для этой модели более чем на **0.01 нат**. Считается `src/plateau.py`; в отчёте измеряемый объект
  называется также *плато*. Любая цифра полосы — это утверждение при `tol = 0.01`, если не сказано
  иное, и §4.25 сканирует этот допуск.
- **пол воспроизводимости**: разброс между запусками веток с одинаковым конфигом, измеренный
  отдельно по устройству и по конфигурации. **0.0150** (CUDA, плотная супервизия), **0.0541**
  (CUDA, только терминальный луп) и **0.0527** (MPS, n = 3; разброс между запусками на MPS
  0.031–0.068). «Внутри пола» значит меньше этого. Все они измерены на 2.5M токенов и применяются к
  утверждениям на 90M; `LIMITATIONS.md` §3 это оговаривает.
- **выигрыш от лупов**: `CE@1 − CE_best` для одной модели, то есть чего стоит ей лупинг. Не путать с
  **ΔCE_best**, который сравнивает две модели каждую в её собственном оптимуме.

### Сопоставимость

Оба лимита соблюдены с запасом. Перплексия зависит от токенизатора (словарь 4096), поэтому
bits/byte — единственная величина, сопоставимая извне, и `SCALE.md` объясняет, почему даже она не
сравнима один в один с опубликованными числами, полученными примерно на 70× большем числе токенов.

## Как это проверить самому

> **Начните отсюда: весов в этом репозитории нет.** Файлы `.pt` не отслеживаются — клон несёт код,
> токенизатор и JSON с эвалами, но не чекпойнт. **Сначала скачайте выложенную модель с Hugging
> Face**, затем направьте команды ниже на неё:
>
> ```bash
> hf download Arsen4ikVar/tlab-looped-transformer --local-dir /tmp/tlab
> #   -> model.pt, tokenizer.json, model.py, README.md
> python src/check_tokenizer_identity.py /tmp/tlab/model.pt --expect-ce1 3.9622 \
>        --tok /tmp/tlab/tokenizer.json
> ```
>
> **Чтобы обучать, а не оценивать**, скачивать ничего не нужно — данные и токенизатор строятся из
> потока:
>
> ```bash
> python src/data.py            # стримит и пакует шарды FineWeb ВЫЛОЖЕННЫМ токенизатором
> python src/train.py           # обучает выложенную конфигурацию
> python src/eval.py checkpoints/<name> --max-loops 64
> ```
>
> **Проверяйте на *скачанной* копии, а не на копии из репозитория.** Сломанная выгрузка невидима для
> проверки, запущенной по локальным файлам.

Выложенный чекпойнт идёт **вместе со словарём, на котором он получен**: несовпадение не бросило бы
исключение, а молча выдало бы CE ≈ ln(4096) = 8.32, что выглядит как сломанная модель. Поэтому гейт
сравнивает со *случайным уровнем*, а не с фиксированным допуском:

```
[gate] vocabulary identity : PASS (|diff|=0.0020 vs |CE-chance|/3=1.4512)
```

```bash
python src/test_model.py       # 13 проверок корректности, включая сверку блока с настоящим Qwen3 (2.4e-07)
python src/test_plateau.py     # 8 проверок статистики глубины, включая намеренную проверку на опровержимость
python src/headline.py check   # сверяет каждое ключевое число с артефактом, из которого оно получено
python src/make_inventory.py --check   # сверяет инвентарь экспериментов с сохранённым JSON
python src/check_caveats.py --strict   # каждое ослабленное утверждение несёт свою оговорку в каждом файле
python src/check_crossref.py --strict  # ни одна цифра из этой папки не отсутствует в ../report.md
```

**Не запускайте `src/train_tokenizer.py` перед эвалом выложенного чекпойнта** — он перезаписывает
`configs/tokenizer.json`, и после этого любой скачанный чекпойнт считался бы на случайном уровне.
Эта ловушка была живой в репозитории, пока её не поймали; см. `FAILURES.md`.

## Чего здесь нет

- Абсолютная перплексия не конкурентна работам без ограничения на данные; `SCALE.md` приводит
  арифметику по токенам, а не оставляет её на самостоятельное обнаружение.
- Ряд результатов получен на одном сиде, и каждый говорит об этом там, где приводится.
